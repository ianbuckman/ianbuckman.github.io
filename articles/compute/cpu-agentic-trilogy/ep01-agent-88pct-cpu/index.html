Agentic AI 让 CPU 翻红，但 Intel 和 AMD 未必是赢家

过去三年「AI = GPU」的叙事，正在被一句「CPU:GPU 走向 1:1」改写。这篇拆解：CPU 为什么重新变重要，以及这波红利最后会落进谁的口袋。

CPU 为什么又火了

过去三年，整个 AI 算力的故事都是关于 GPU 的。英伟达从 1 万亿美金市值翻到 4 万亿，台积电的 CoWoS 产能成了全球科技公司的硬通货。

但 2026 年 4 月底到 5 月初的 5-6 周里，做 CPU 的 Intel 累计涨了 116%，AMD 涨了 124%——同期 NVIDIA 相对平淡。CNBC 把这一轮市场动作写成「Wall Street sees 'changing of the guard in AI'」。

起点是 4 月 23 日 Intel Q1 财报电话会议。CEO Lip-Bu Tan 说了一句话——「未来数据中心里 CPU 和 GPU 的比例，会从今天的 1:8 走到 1:4，最终走向 parity（1:1）甚至 CPU 反超 GPU」。市场把这句话当成了一个分水岭。

为什么这个时候 CPU 重新成了话题？答案藏在一个被大部分人忽视的数字里：在一个完整的 agent 工作流里，GPU 真正在算的时间只占大约 12%——剩下近 88% 的时间都不在 GPU 上，而是花在任务编排、工具调用，以及「会话挂在 CPU 上、等网络和 LLM 返回」上。而且更反直觉的是——GPU 推理越快，它在端到端延迟里的占比就越低，agent 的瓶颈反而越往 CPU 这一侧挪。

这篇文章想讲清楚三件事
  1. 为什么 Agentic AI 让瓶颈从 GPU 移向 CPU——以及"88%"这个数字从哪来
  2. 并发场景下，CPU 才是数据中心真正的扩展瓶颈
  3. CPU 品类在涨，但增量价值为什么不流向 Intel 和 AMD

一、Agent 工作流里，CPU 才是大头

AI 的使用方式在 2025 年发生了一次范式切换：从「单次推理」（输一句话、回一段话）切换到「agent 工作流」（给一个高层目标，模型自己规划、调工具、读文档、再推理、再调工具）。一个 agent 任务往往涉及 10-30 轮 LLM 调用 + 几十次工具调用。前者是 GPU 的舒适区，后者是 CPU 的舒适区——因为后者本质上是「连续的状态管理 + 大量 I/O」。

你以为 agent 在等 GPU，其实在等 CPU

大多数人默认「AI = GPU」，所以会觉得 agent 慢是卡在等 GPU 算。但真相相反：一次 agent 任务的时间，大部分根本不花在 GPU 上。考虑一个简化模型：5 轮 LLM 推理 + 5 轮工具调用。agent 编排这一侧的工作（解析 JSON、HTTP 往返、PDF 解析、向量库读写，外加等网络和 LLM 返回）不会因为 GPU 变快而变快——它就在那里，恒定约 30 秒。但 GPU 单轮推理在持续提速：H100 时代 4 秒，Blackwell 时代 2 秒，Rubin 时代约 0.8 秒。

注意一个细节：PDF 解析单步就吃掉 8 秒，比 GPU 整个任务的三分之二还多。这种「看起来不智能但巨耗算力」的工作——HTML 解析、JSON 序列化、向量库查询、状态对象的复制——在 agent 工作流里到处都是。每一项都不大，但加起来就是 agent 整体性能的瓶颈。而且它们都跑在 CPU 上，且必须跑在 CPU 上。

那占了 60% 的「网络 + 排队」呢？单看一个任务，它确实只是 CPU 在干等，谈不上什么价值。但恰恰是这段「大部分时间在等」的特性，才是下一章的伏笔——正因为每个会话大半时间都在等，一台 CPU 才能同时托管成千上万个会话。单任务视角里的「浪费」，到了并发视角就成了 CPU 的红利来源。

二、并发：CPU 真正的扩展维度

到这里只解释了「单个 agent 任务里 CPU 的占比」。但真正决定数据中心 CPU 需求的不是单任务，是并发。

考虑一家 SaaS 公司给 1000 个企业客户提供 AI agent 服务，每个客户随时可能发起一个 agent 任务，每个任务持续 1-3 分钟、且大部分时间在等。用 GPU 来「管理」这 1000 个会话——做不到。GPU 只能一次跑一批同质化的任务，托管不了「几千个会话各做各的、大部分时间在等」这种场景。这是它的设计取向，不是缺陷。

CPU 完全相反。它天生就是为「同时托管海量会话」设计的——一台 192 核服务器可以同时挂着几千到上万个会话，自动让「正在等数据」的会话先歇着、把「数据刚到」的叫醒接着干。Gmail、Stripe、Shopify 同时服务几千万用户，靠的就是这套机制。而 agent 编排，本质上就是同一类负载——只是过去它叫「后端服务」，现在换了个名字。

CPU 按「并发」扩展，GPU 按「吞吐」扩展

这是理解 AI 时代算力分工的最核心一句话。

维度 CPU GPU
扩展单位并发会话数tokens/sec 吞吐
适合负载I/O 密集、大部分时间在等、状态持久算得越多越值、一批同质任务
同时托管的 agent 会话5000-10000 量级（单台 192 核，工程估算）个位数（且必须批量推理）

这两件事互补，不竞争。理想的数据中心不是「GPU 替代 CPU」，而是「CPU 服务器托管几万个 agent 会话，每个会话在需要推理时把请求送到附近的 GPU 服务器」。

这就解释了一个之前看起来奇怪的现象：为什么过去两年市场上突然冒出 128 核 Bergamo、192 核 Turin Dense、288 核 Sierra Forest、96 核 Graviton 4 这种"核数怪兽"？它们的设计目标根本不是「让单线程跑得更快」，而是「让单台服务器塞进尽可能多的并发会话」。在 agent 工作流到来之前，这种设计的市场需求其实有限——主要是 web hosting 和数据库；agent 工作流出现之后，这种 CPU 突然变成了刚需。

这就是 Lip-Bu Tan 说"CPU:GPU 比例从 1:8 走向 1:1"的真实含义——不是说每张 GPU 旁边要配一颗 CPU，而是说数据中心里"专门用于 agent 编排的 CPU 服务器"会作为新的独立类目快速增长。Bank of America 预计数据中心 CPU 的 TAM 从 2025 年的 270 亿美金增长到 2030 年的 600 亿美金（翻倍以上），主要增量就来自这一层。

三、价值流向：CPU 复兴的诡异之处

讲到这里，逻辑链已经完整：agent 工作流 → CPU 时间占比单调上升 → 并发场景需要大核数 CPU → 数据中心 CPU TAM 翻倍。

但这一轮 CPU 复兴有一个特别值得注意的反常之处：增量价值不流向历史的 CPU 双寡头。

价值链的三层塌陷

技术史上的典型剧本是这样的：某个品类繁荣，在位者吃掉大部分增量。智能手机抬起了 Apple 和 Samsung，云抬起了 AWS 和 Azure，社交媒体抬起了 Meta。

但 CPU 这一轮不一样。CPU 品类在涨，但 Intel 和 AMD 在过去五年里被同时从三个方向掏空：

第一，超大规模云厂商自己设计芯片。AWS 有 Graviton（已迭代多代），Google 有 Axion，Microsoft 有 Cobalt，Meta 有自研 Arm。这一层把 IP 价值捕获走了——以前云厂商付钱给 Intel/AMD 买 CPU，现在自己做。几乎所有新进入者都选了 Arm——因为 x86 不能被授权，只有 Intel 和 AMD 能造。

第二，TSMC 拿走了制造利润。Intel 自己有晶圆厂，但 18A 工艺还在爬产能；超大规模云厂商的自研 CPU 全部在 TSMC 上流片。也就是说，每一颗自研 Arm CPU 卖出去，制造利润流向 TSMC，而不是 Intel 的晶圆厂。

第三，云厂商自己装数据中心。系统集成的利润——服务器组装、机架设计、整机销售——这些以前是 Dell、HPE、Supermicro 的活，现在云厂商越来越多地直接和 ODM（鸿海、广达、纬颖）合作，绕过传统 OEM。

Intel 一次性失去了三层价值捕获，AMD 也同步失去了 IP 设计与系统集成两层（AMD 一直是 fabless，第二层与它的关系本就有限）。它们拿到的，只剩下「客户兼容性需求 + 双寡头剩余份额」——这是一个会持续被压缩的市场。

NVIDIA 是隐形的 CPU 大厂

这里还有一个被严重低估的玩家：NVIDIA 在 2025 年已经成了全球第二大服务器 CPU 厂商（按出货量）。

每一台 GB200/GB300 卖出去，都带走一颗 Grace CPU；每一台 Vera Rubin 卖出去，都带走一颗 Vera CPU。2025 年 NVIDIA 出货约 250 万颗 Grace CPU，2026 年 Vera 接力。这些 socket 都是 Intel 和 AMD 永远没有机会竞标的——因为 NVIDIA 把 CPU 与 GPU 通过 NVLink-C2C 集成在同一个系统模块里，作为整机方案捆绑销售。

这是 NVIDIA 整个 AI 帝国里最隐蔽但最关键的一手棋：通过把 CPU 也捆进系统，NVIDIA 把自己从「GPU 供应商」升级成了「完整 AI 计算系统供应商」，每一代产品都同时吃掉一个 GPU 利润和一个 CPU socket。

这一轮 CPU 红利，最干净的受益方是谁

回到产业格局。如果接受「agent 工作流推动 CPU TAM 翻倍」这个逻辑，但同时承认「价值不流向 Intel/AMD」的现实，那么最干净的受益方有三个：

Arm Holdings——所有非 x86 服务器 CPU 出货的版税收费亭。AWS Graviton、Google Axion、Microsoft Cobalt、NVIDIA Grace/Vera、Apple Silicon、Ampere——所有这些都基于 Arm 指令集，每出货一颗 Arm 都收一笔授权费。Arm 的商业模式不需要赌任何一家 CPU 厂商赢，只要「Arm 阵营在数据中心新增份额上持续蚕食 x86」就行——而这个趋势在 2025 年已经基本明朗。

TSMC——所有人的代工厂。Apple、NVIDIA、AMD、AWS、Google、Microsoft 的所有先进制程 CPU 全部在 TSMC 流片。无论最后谁赢，TSMC 都赢。HPC 业务在 TSMC 收入里的占比已经从 2023 年的 51% 涨到 2026 年的 58%，NVIDIA 已经替代 Apple 成为它最大客户。

供应链二阶受益方——HBM（SK Hynix 62% 份额，HBM 业务毛利率约 79%）、CoWoS 封装（月产能从 2025 年底 7.5 万片扩到 2026 年底目标 12-13 万片，仍供不应求）、电源（MPS、Vicor，机架功耗从 H100 时代的 10kW 涨到 Kyber 机架的 600kW）、基板（Ibiden）。这些都是「AI 算力涨多少，它们就跟着涨多少」的环节，确定性比押注单家 CPU 厂商高。

至于 Intel 和 AMD——它们在 2026-2027 年会吃一波周期性供给红利（CPU 需求增速超过任何一家厂商的扩产速度，5 月那一波股价反应就是市场在为这个逻辑重新定价），但这是周期，不是结构。阶段性的供需机会和长期的产业格局，要分开看。

结尾

GPU 越快，它在 agent 工作流里的时间占比反而越低，瓶颈越往 CPU 这一侧挪。AI 从「一次问答」进化到「连续行动」之后，瓶颈不再只是 LLM 推理算力本身，还有围绕算力的调度，以及对海量会话的托管——这就是为什么「GPU 只占一成」不是临时现象，而是 GPU 越快就越成立的结构性规律。

未来一两个季度可以重点观察的指标：

  1. 超大规模云厂商资本开支里，CPU 服务器（不含 GPU bundle）的占比是否在上升；
  2. AWS Graviton、Google Axion、Microsoft Cobalt 的出货量增速——这是「自研 Arm 替代 x86」逻辑在兑现的最直接证据；
  3. NVIDIA Grace/Vera 的出货量与 GPU 出货量的比例变化；
  4. Arm Holdings 的版税收入结构里，云数据中心占比的变化。

CPU 这个被 GPU 抢戏三年的品类，现在重新回到 AI 算力的故事中央。但这一次，故事的主角名单不一样了。

x86 vs Arm 的最后一战——这从来不是 ISA 之争，是商业模式之争

你以为 Arm 比 x86 省电？Phoronix 实测里 AMD EPYC 9965 Turin Dense 的 perf/watt 反而压过 AmpereOne——「Arm 省电」是个被卖给读者三年的神话。Arm 真正赢的不是 ISA，是商业模式：Arm 卖 IP（hyperscaler 12 个月自研一颗 CPU），x86 只卖芯片。下一篇拆 1981 年 IBM 留下的「化石」结构、EAG 不是反攻而是 x86 阵营的体面投降，以及 Meta 买 Rivos / NVIDIA 移植 CUDA 到 RISC-V 这「下下一战」的期权。
